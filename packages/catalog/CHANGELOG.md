# @fluxnative/catalog

## 0.0.1

### Minor Changes

- 1a908b7: Five fixes the template factory's first batch (fluxbuilder-template, process 3.2.0) found by forking or replacing recipes:

  - `Composer`: the send button is 44 pt (was 36 in a 42 pt pill) and keeps its full colour at rest; an empty send does nothing instead of fading the button below 3:1. Visual change: the send no longer dims while the field is empty.
  - `SegmentedControl`: tracks are 36 / 44 px (were 32 / 40) and each segment's touch target is padded to 44. Visual change: taller controls.
  - `StatTile`: `valueRole` (the value in a brand's `numeric` face, a mono family) and `valueColor`.
  - `ScreenHeader`: `backIcon` ('platform' by default, or 'chevron' / 'arrow' on every platform when the design draws one).
  - `AiBadge`: `mark`, the brand's own glyph, or `null`; the default sparkle is a generic tell.

  `CRAFT.index.md` rule 10 adds non-text contrast: 3:1 for icons, borders and a control's resting fill.

- 1a908b7: A brand's named font family now works on Android. React Native takes one family name per role, and Android ships none of the named families a brand may use (Georgia, Menlo, Courier), so a template's display face silently fell back to the system sans there. A template's `theme/tokens.ts` now picks per platform at run time: iOS draws the named family, Android the stack's generic (`serif`, `monospace`), the web the whole stack. It imports `Platform` from react-native only when a role names a family; the kit's own tokens are unchanged.
- 1a908b7: Brand files work end to end with manifest v2. `emit`, `update` and `check` take `--brand`; the manifest records `inputs.brand`, `brandPath` and `brandFiles` (a sha256 per brand file, so another tool can verify the DNA without resolving it), `check` names the brand file that changed, and `update` re-renders from the recorded `brandPath`. The brand reader, validator and sys emitters move to `@fluxnative/tokens/brand`, so the package's main entry is only the generated constants an app bundles.
- 1a908b7: AI pack v0: what an AI screen in a Flux template needs, over the host's `ai` capability (`docs/topics/ai.md`).

  - `components/bridge.ts`: the `bridge.ai` contract (`FluxAi` with `chat` (streaming through `onDelta`, abort through `signal`), `generateImage`, `transcribe`, `describeImage` and `quota`; `AiResult<T>`, `AiError`, `AiMessage`) and an `ai()` helper. Every existing export and member is unchanged.
  - `useAiChat({ purpose?, system?, initialMessages? })` → `{ messages, status, streamingId, error, retryAfterMs, send, stop, retry, reset }` and `useAiTask(run)` → `{ status, result, progress, error, retryAfterMs, start, cancel, reset }`. Calls abort through an `AbortController` on stop, cancel and unmount; without the capability the status is `unavailable` and nothing throws. Typed errors map to `quota`, `unavailable` or `error`.
  - `StreamingText` (minimal Markdown, caret, a single screen-reader announcement when streaming ends), `Composer` (send and stop in one button, core `KeyboardAvoidingView`), `MessageList` with `MessageBubble` (anchored to the bottom in chronological order, follows a streaming reply, keeps the reader's place, "Jump to latest"), `ScanFrame` (viewfinder corners and scan line) and `AiBadge` ("Generated by AI"). All respect Reduce Motion and read the palette and the `type`, `shape` and `space` tokens.
  - `components/aiState.ts` (the chat and task state machines and their controllers) and `components/markdown.ts` import no React, so they are unit-tested with `node --test`.

- 1a908b7: `fluxnative-catalog index` writes `docs/llm/CATALOG.index.md`: the ≤ 8 KB index a model reads before it writes a Flux template screen, generated from the layer itself (component props with their closed values, token roles, the dialect rules and one example). `pnpm tokens` regenerates it and `pnpm tokens:check` fails on drift.
- 1a908b7: Catalog layer and the closed `flux/glass` contract.

  - `@fluxnative/catalog` (new): emits a dependency-free `theme/tokens.ts`, `components/Icon.tsx` and ten primitives (Press, Reveal, Skeleton, Scrim, Sheet, Chip, Button, IconButton, StateView, SectionHeader) into a Flux template, with colour overrides and a `.fluxnative-ui.json` manifest; `emit --check` catches drift.
  - `@fluxnative/icons` (new): one closed icon table (SF Symbol, Material Symbol, SVG path) and an `<Icon>`; `FluxTabs.Tab` takes `iconName`.
  - `@fluxnative/glass`: the `flux/glass` contract (`contract.ts`) with generated host files for the FluxBuilder web preview and FluxNative Expo under `hosts/`, checked in CI.
  - `@fluxnative/tokens`: `destructive-foreground`.
  - `@fluxnative/tw-runtime`: shadows, leading/tracking, transforms, border-x/y, max-w-\*, screen sizes.
  - `@fluxnative/ui`: `AppBar backLabel`, `TabBar shape` (Material 3 bar on Android), component render tests; `react-native-svg` is now a required peer.

- 1a908b7: `fluxnative-catalog update`, manifest schema 2 and self-identifying files.

  - `update --to <files> [--colors <json>] [--only A,B | +A,-B] [--dry-run] [--json] [--merge --base-dir <dir>]`: writes the catalog's copy over every file that still matches `.fluxnative-ui.json`, deletes the pristine files the catalog no longer ships, and reports hand edits with a diff instead of overwriting them (exit 2). `--merge` merges a hand-edited file with `git merge-file --zdiff3` against an earlier emitted copy. Declared forks are never written (a fork whose catalog copy moved on is reported); compositions are never touched.
  - Manifest schema 2: `catalog { version, commit, repo }`, `inputs { colors, colorsPath, brand, brandPath, only }`, `files`, plus the owner-written `forks`, `compositions` and `applied` (reserved for release codemods). Schema 1 manifests are read and upgraded on the next write. This package's own `files/.fluxnative-ui.json` records `commit: null`.
  - `check` verifies a template against its own manifest (file hashes, input hashes) instead of the current catalog; `check --upstream [--strict]` lists what `update` would change. `emit --check` still compares bytes.
  - Every emitted file under `components/` and `theme/` starts with a header naming it and linking the catalog docs (no version number, covered by the hashes); the sources in `files/` stay header-less.
  - `--only` follows the files' relative imports instead of a hand-written table, which also ships `bridge.ts` with `Reveal`, `Skeleton` and `Sheet` (their `useReducedMotion.ts` imports it).
  - API: `Manifest` is the schema 2 shape (`inputs.only`, `inputs.colors`); new `update`, `checkTemplate`, `componentDeps`, `importGraph`, `parseManifest`, `loadManifest`, `upgradeManifest`, `catalogCommit`, `emittedHeader`.

- 1a908b7: The screen graders (dialect, props, tokens, shadow-primitive, coverage, typecheck, extract) move into `@fluxnative/mcp` (`src/graders`), next to the `validate_screen` tool that uses them, and their tests now run in CI.

  The eval runner, the judges, the AI-look panels, `evolve` and the template-catalog `learn` command are now FluxBuilder's private tooling and leave this repository:

  - `fluxnative-catalog learn` is removed.
  - The `eval`, `evolve` and `judge` scripts are removed.
  - `docs/topics/evolution.md` is removed.

  The index gates every release must pass (no phantom name, every component documented, every recipe with evidence) are now a catalog test.

- 1a908b7: `CATALOG.index.md` lists the 90 `Icon` names (closed; any other name fails tsc). The first real eval run showed every model guessing Lucide names (`alert-triangle`, `map-pin`, `user`); with the list, Opus 5.5 went from 38% to 100% first-try, Sonnet 5.5 from 62% to 100%, Haiku 5.5 from 23% to 85%. To stay under 8 KB, closed string values are written `a/b` (`variant?(primary/secondary)`), and the `interaction` row and a tagline that repeated rule 1 are gone.
- 1a908b7: Fifteen recipes, each shaped after real apps on Mobbin and after the copies the 52 catalog templates had written by hand (the evidence is in `packages/catalog/registry.meta.json`):

  - `ScreenHeader` (back, title, trailing actions, a large title), `SearchField` (glyph, clear, Cancel), `TextField` (`kind` picks the keyboard; password Show/Hide; helper and error), `ListRow` and `ListGroup` (settings and menu rows on one card with inset rules), `SegmentedControl` (a sliding thumb or an underline), `Notice` (inline info / success / warning / error with an action or a dismiss), `Stepper` (one adjustable element for screen readers), `BottomBar` (the pinned action bar with a summary line or a leading slot), `Avatar` (photo, else initials on a palette tone; a status dot), `ProgressBar` (eased fill, indeterminate sweep), `PageDots`, `Rating` (halves, value, count, input mode), `Photo` (skeleton while loading, fallback on error), `Divider`, and the `useCountdown` hook.
  - All read the token roles (`type`, `shape`, `space`, `elevation`, the palette) and the interaction profile, respect Reduce Motion, and carry a screen-reader name. Nothing existing changed.
  - `fluxnative-catalog registry` writes `registry.json`: every component with its props (read from the sources), relative imports, when to use it, screen archetypes, the hand-written names it replaces and the evidence it was shaped from. `pnpm tokens` regenerates it and `pnpm tokens:check` fails on drift.
  - `CATALOG.index.md` lists all 40 components and stays under 8 KB: the palette folds each `x` / `x-foreground` pair, `on*` props drop their `(fn)` marker, node slots are listed once in a legend, and a `ButtonVariant`-style alias names the row that spells it out.

- 1a908b7: Two recipes from the template catalog's top `learn` candidates, grounded on Mobbin:

  - `SkeletonRows`: a list while it loads, rows of a circle, square or no leading shape and one to three bars (the second shorter), an optional trailing value pair and hairlines, one busy "Loading" element for screen readers. 17 templates drew it by hand; shaped after Instagram, Quizlet, ChatGPT, talabat and Wise.
  - `StatTile`: one number with a label, a unit, a change chip coloured by trend (filled, with its ink, so it passes 4.5:1) and a caption; card or plain, `md` or `lg`, a button with `onPress`. A local `Stat` in 8 templates; shaped after Substack, Fitbit, Tonal and MacroFactor.

  The catalog index budget moves from 8 KB to 9 KB: fitting 8 KB had started to cost meaning (a brace group of icon names read as a name `x` in the third real eval round). Rows still leave out the optional labels that only rename English defaults and the props a component's metadata lists in `indexOmit`; `registry.json` keeps every prop. `Icon` now accepts 46 names from other icon sets (`x`, `user`, `map-pin`, `shopping-cart`…), each drawn as the kit glyph it means, and `ProgressBar`'s `progress` is optional (default 0) for the indeterminate case.

- 1a908b7: What `fluxnative-catalog learn` found the merged template catalog forking or wrapping (fluxbuilder-template, 72 templates, 13 October 2026):

  - `Composer` (sinew-ai-coach's fork): the one-line field is 52 pt, so the 44 pt send sits 4 pt in; a tap on the send while the field is blank focuses the field; `disabled` no longer fades the field, so a placeholder that says why ("Plans refill at 06:00") stays legible, and the send dims as before. The `leading` and `trailing` slots centre on the one-line field. Visual change: a taller field.
  - `SearchField` (orvia-health's fork): `readOnly`, not editable but at full strength; `disabled` still fades.
  - `ProgressBar` (gridfront-weather's fork): `square`, radius 0 on the track and the run.
  - `PageDots` (laudine-designer-boutique's fork): `variant="dots"`, equal round dots with the others at 55%, so the faded dots read at 3:1 against the ground and against the current one (30% is 2:1).
  - Text actions reach 44 pt (dimity-assistant measured 34): `Notice`, `SectionHeader`, `Snackbar`, `SearchField` Cancel and `TextField` Show/Hide take `textActionSlop(type.label.lineHeight)` from `Press` (12 on the kit's 20 pt line, was 6 or 8). No visual change.

  `CRAFT.index.md` rule 10: a locked field whose placeholder says why is not faded either.

- 1a908b7: `TabBar`: the tabs at the foot of an app. The template catalog drew 53 of them by hand: 29 floating capsules and 24 edge bars, 15 with wrong tablist, tab or selected roles. The recipe covers both shapes, matching the iOS 26 and Material 3 tab bars on Mobbin (TIDE, GitHub, Fresha, Craft, Strava, Docusign).

  - `shape`: 'floating' (an inset capsule over the content) or 'bar' (full width under a hairline).
  - `labels`: 'always', 'active' or 'none'.
  - `indicator`: 'lens' (`accent` behind the tab, an M3 well on a bar), 'solid' (`primary`) or 'tint'. In 'tint' the glyph is `primary` and the label `foreground`, because `primary` on `card` is 4.0:1, under 4.5:1 for an 11 px label.
  - `tone`: 'default', 'inverse' or 'glass'.
  - `action`: a round button at the end, or a disc raised between the tabs.
  - `overlay` and `bottom`, plus `tabBarClearance()` to pad content under an overlay bar.

  Accessibility: a tablist of tabs, the current one selected, badge counts in the names, 44 pt targets, and `onReselect` for a tap on the current tab.

  - `Chip` with `accessibilityRole="tab"` now reports `selected` instead of `checked`.
  - `IconButton` exports `badgeMark` and `withCount`.
  - `learn` no longer counts tab bars and docks as host chrome; they map to `TabBar`.
  - CRAFT rule 11: tabs are `TabBar` until `flux/navigation` draws them.

- e6edb0f: Defaults the template factory's batch-02 had to fork or wrap (fluxbuilder-template, 13 October 2026):

  - `Rating` `countFormat="full"` shows every digit ("1,186 reviews"); 'short' ("1.2K") stays the default.
  - `Press` adds its press scale after the caller's `transform`, so a tilted card keeps its rotate.
  - `StatTile` `labelRole` sets the label's type role (default 'bodySm').
  - `PageDots`: the faded dots are at 55% in the pill variant too. That reaches 3:1 against the ground on all 72 catalog palettes; 30% reached none. Visual change: darker dots.
  - `StateView`: the action is primary in every tone. A secondary fill rested near 1.2:1 on a card. Visual change: the neutral state's button is filled.
  - `ProgressBar`: an indeterminate bar under Reduce Motion holds a still run in the middle instead of an empty track.

- 1a908b7: The primitives read token contract v0.1, and four recipes join the catalog.

  - Defaults come from `theme/tokens`: `Press` takes its haptic, press scale, hit slop and spring from `interaction.press`; `Reveal` its offset, duration and stagger from `interaction.reveal`; `Skeleton` its mode, colours and timing from `interaction.skeleton`, with a new `color` mode that pulses between two palette roles. Text uses `type` roles and corners `shape` roles (`Button`, `Chip`, `IconButton`, `Sheet`, `StateView`, `SectionHeader`, the `Skeleton` default radius). With the kit's tokens nothing changes on screen; a test renders every primitive against its previous source to prove it. A brand that changes a role or the profile now restyles them.
  - `Button`: `size="xl"` (60 px), `labelRole` (a `type` role, used as is), and the exported comp table `buttonHeight`.
  - `IconButton`: `variant="outline-on-surface"` (a `card` face with a hairline ring), `badge` also takes a boolean (`true` draws a dot, `false` hides it), `dot`, and a count or text badge now joins the screen-reader name ("Bag, 3"). Hit slop and corners follow the profile and `shape.control`.
  - `StateView`: `variant` (`'inline'`, the same as `inline`, or `'card'`) and `badge` (an icon in an `accent` circle above the title). A title on a card surface (banner or card) is drawn in `card-foreground`.
  - New recipes: `useCountUp(target, { duration?, delay?, enabled? })`, `Toggle`, `Snackbar` and `commerce/ProductCard` (emitted as `components/commerce/ProductCard.tsx`, with `formatPrice`).
  - `emit`, `update` and `check` handle a component in a sub-folder: its name is its file's base name (`--only ProductCard`), and two components with one name are refused.

  Visual: none with the kit's tokens.

- 1a908b7: Token contract v0.1: a template's design DNA beyond colour.

  - `@fluxnative/tokens`: the DTCG reader takes `fontFamily`, `typography` and `shadow`, with aliases inside composite values. New sys groups `font`, `type`, `shape`, `elevation`, `interaction` and `layout` (constants plus `TypeRole`, `ShapeRole` and `ElevationLevel`) default to what the catalog primitives do today. Eight colour roles join both schemes: `foreground-soft`, `border-soft`, `success-foreground`, `warning-foreground`, `inverse`, `inverse-foreground`, `tertiary` and `tertiary-foreground`. Brand files (`brand.tokens.json`, `brand.dark.tokens.json`, or a subset of DTCG Resolver 2025.10) load through `readBrandFiles`. `validateBrand` and `resolveBrand` check them with deterministic rules: contrast, the type scale, system fonts only, shape, elevation, motion, interaction, layout and closed keys. The Uniwind theme adds `rounded-<shape>` and `text-<role>`.
  - `@fluxnative/tw-runtime`: resolves `rounded-<shape>` and `text-<role>`. As in Tailwind, `leading-*`, `tracking-*` and `font-*` win over a role.
  - `@fluxnative/catalog`: `emit --brand <file | resolver | folder>` (exclusive with `--colors`), `render({ brand })`, `emitTokens({ brand })` and `loadBrand`. `theme/tokens.ts` appends the sys sections and `density`. With no brand, the existing sections don't change apart from the new colour roles.

### Patch Changes

- 1a908b7: `npx fluxnative-catalog` now runs from an installed copy: a plain-JS launcher strips the TypeScript of this package and the other `@fluxnative` packages it imports (Node refuses to under `node_modules`). Colour descriptions are resolved through `@fluxnative/tokens`' exports, so an npm install emits the same bytes as the monorepo. Tests no longer ship in any package tarball, and every package has a README.
- 1a908b7: What an OpenAI model (gpt-6.1-sol, through Codex CLI) misread in the catalog index, its first cross-vendor run:

  - `arrow-down-right` icon (SF `arrow.down.right`, Material `south_east`): the falling trend beside `arrow-up-right`. The model reached for it and the table had no such glyph.
  - `Photo` `height` takes a `DimensionValue` like `width`, so `height="100%"` fills the parent. The model wrote it in two runs.
  - Index rule 7: a recipe before a hand-drawn view (`MessageList` for a chat, `ListRow` for a row, `TabBar` for tabs, `StateView` for empty and error). The model's coverage was the lowest of every model run.

- 1a908b7: The default light `destructive` is `#d70015` instead of `#ff3b30`: 5.4:1 on white and white on it, so error titles, error helpers and danger fills pass 4.5:1 (the old red was 3.55:1). Visual change: error states are a deeper red. Templates that set their own `destructive` are unchanged. Found by the pairwise judge on the first real eval run.
- 1a908b7: The emitted `Icon` puts `style` on a wrapping `View` instead of `<Svg>`, so FluxNative's web preview typecheck no longer rejects it (`StyleProp<ViewStyle>` is not react-native-svg's style type there).
- 1a908b7: `Icon` no longer passes `accessible` / `accessibilityLabel` / `accessibilityRole` to `<Svg>`: react-native-svg's web build forwards unknown props to the DOM `<svg>` and React logs "Received `false` for a non-boolean attribute `accessible`" for every icon. A decorative icon is now a bare `<Svg>`; a labelled one is wrapped in a `View` that carries the accessibility props (role `image`). Same change in the catalog-emitted `components/Icon.tsx`.
- 61c3566: `StateView` `titleRole`: the block title in a type role as the brand sets it (for example `'headline'` for its display face), instead of the recipe's 18/28 semibold. The banner keeps its own title. fluxbuilder-template batch-02 forked StateView for exactly this (parlora-voice-rooms).
